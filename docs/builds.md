# Signed installed build bytes

Manifest0.3.11 optionally declares `entry.executables`, with exactly the same targets as `entry.installs`. These are full own-tree executable paths strictly within the corresponding portable, non-overlapping build prefixes. A present declaration binds the signed list's `entry`; it does not grant launch authority. Original signature reads and artifact reuse compare it in both the checked original and requested current version. A manifest-only executable change cannot reuse a receipt for a different entry. The canonical signed bytes remain unchanged. Declarationless legacy manifests retain explicit fixed-worker selection; manifest-selected workers refuse absence rather than guessing a filename.

E12/E16's exact encoding is recorded before implementation in command-center's permanent files record and the Build V2 cycle's `installed-contract.md`. `BuildFile`, `BuildList` and `SignedBuild` are exported root schemas/types. `canonicalBuildList` and `parseBuildList` produce and validate the same bytes as the native App verifier.

The payload is UTF-8 JSON without whitespace or trailing newline. Keys are exactly `domain`, `folder`, `version`, `target`, `prefix`, `entry`, `files`; domain is `ew.build-files.v1`. Files are sorted by ASCII path, with keys `path`, `sha256`, `size`, `executable`. Folder/version are immutable platform identifiers. Prefix and exact executable are signed. Every file is under the prefix; the entry is a listed executable. Paths are portable ASCII, case-insensitively unique, and cannot contain traversal, reserved device names, trailing dot/space, or file/directory conflicts. Sizes and their sum are safe integers; at most 10,000 files are admitted. The canonical vector is shared byte-for-byte with the native App regression.

`BuildList` validates structural and semantic fields; the encoder sorts otherwise valid input. `parseBuildList` additionally rejects alternate JSON encodings, duplicate/unknown keys and unsorted file bytes. Emitted JSON schemas describe structural fields; consumers must also invoke these runtime helpers for cross-field checks and canonicality. `SignedBuild` is the envelope `{payload, signature}`. Its schema does not authenticate a signature. Only the trusted signing service creates detached minisign signatures; the App's native verifier uses the App-controlled builds key and refuses missing configuration.

SDK's check runner uses these bytes and sends prefix/entry/payload plus the payload SHA-256 to its signing callback only after the other five lines and scans pass. It requires the callback's hash to match these bytes. The signed envelope and hash become evidence for platform persistence. This does not configure a signer, create a key, sign an artifact or replace the native cryptographic verification.
