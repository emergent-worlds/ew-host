# Runtime worker transport

E11's server and hidden runner can adapt a worker with `workerTransport(worker)`, then pass that transport to an explicit core `HostBridge`. The worker's core uses `connectCore` over its own parent endpoint. The adapter is an in-process transport, not a sandbox, a worker launcher, or a loader for an engine.

The adapter supports Node's `message`, `messageerror`, `error`, and `exit` event-emitter API and Bun's `message`, `messageerror`, `error`, and `close` EventTarget API. Node passes the payload directly; Bun places it in `MessageEvent.data`. Shipped code uses structural endpoint types and no runtime-specific imports. Node and DOM Worker types are checked by TypeScript; Bun's native Worker is exercised at runtime.

Construct the transport immediately after creating the worker. It installs message and lifecycle handlers immediately, retaining early messages until `onMessage` subscribes. The internal startup guard is 1,000 queued messages and does not bound ordinary attached traffic. `close()` unregisters handlers, clears queued messages, notifies `onClose` observers, and requests worker termination once. Send failures, message decoding failures, worker errors, and observed worker exit close the transport. Errors use fixed descriptions and omit the worker's exception text.

Graceful shutdown is separate: send a correlated core `quit` request and let its handler finish the final save before closing. This adapter's close notification means termination was requested or observed by the runtime; it does not prove that a native process completed every shutdown step. Browser workers do not supply Bun's native `close` event, so browser callers must arrange local disposal rather than infer remote exit detection from that event name.

Run `pnpm check:runtime-workers` for both real runtimes. `pnpm test` includes the same checks, with Bun skipped only when it is not installed locally; CI installs Bun 1.4.3 before testing. The fixture exchanges ready, grant, read, status, and correlated state replies, then checks worker exit and an uncaught synthetic failure in each runtime. Unit fixtures verify startup buffering, listener removal, idempotent disposal, close notification, and sanitized send errors. These checks do not load a real engine, exercise WebAssembly, or compile a server executable.

Runtime references: [Node 24 worker threads](https://nodejs.org/docs/latest-v24.x/api/worker_threads.html) and [Bun workers](https://bun.sh/docs/runtime/workers), read 2026-10-15. Bun's documentation says messages can be dropped if the worker installs its global message handler after a top-level await; install that listener synchronously or use a parentPort implementation that queues until its listener attaches. Its `close` event marks termination before the worker necessarily finishes exiting. The test fixture installs Bun's handler before any awaited import. [Bun's CI guide](https://bun.sh/guides/runtime/cicd) documents the setup action used by this repository.
